源码与构建说明

普通用户不用编译。安装 APK、使用随附的 Windows 程序即可。

03-源码与开发资料/Codex-Pocket-Source-0.4.0.zip 是完整项目源文件，含 TypeScript、Kotlin/Compose、测试、脚本与 npm 锁文件；不含生成的 dist、node_modules、SDK/JDK/Gradle 缓存、配对数据或签名私钥。

电脑程序

建议 Node.js 24 x64；解压源码到自己的开发目录后，在项目根目录执行：

npm ci
npm run build
npm test

npm test 的浏览器集成测试默认使用 C:/Program Files/Google/Chrome/Application/chrome.exe，测试用远程调试端口也需未占用；开发机需安装 Chrome，不能将未满足前提的失败当成功。

开发时先按用户教程把 Codex 从配套入口以本机调试方式启动；源码程序使用默认本机 9222。

运行 npm start 时默认数据目录为当前用户 LOCALAPPDATA/CodexPocket；发布启动器默认放在自身 data。

不要同时运行两个监听同一端口的连接程序。POCKET_STATE_DIR 可用于单独的测试数据目录，绝不指向别人的运行数据。

node scripts/package.cjs 会在源码上一级的 package 目录重新生成 Codex-Pocket-Windows 和 Codex-Pocket-Source 暂存文件夹；请先阅读脚本，因为这两个固定名称的旧暂存目录会被重建。

安卓程序与签名

工具链：JDK 17、Android SDK/Build Tools 35、Gradle 8.13；Kotlin/Compose 依赖由 Gradle 下载。本包不附几十 GB 的工具链或缓存。

推荐用 Android Studio 打开 android 目录、设置 SDK 和 Gradle 8.13；也可按现有 scripts/build-android.ps1 要求，在项目上两级的 work/toolchain 下配置 jdk-17、android-sdk、gradle-8.13。脚本会暂时映射空闲英文盘符，并在退出后撤销。

本源码的签名配置指向 android/keystore/development.jks，alias codexpocket；原始 keystore 不公开，因此干净源码不能不配置签名就构建原签名 APK。

请先把 applicationId 改为你自己的标识，例如 cn.example.codexpocket，再用自己的密钥修改 signingConfigs；不要把新签名 APK 当作本包的覆盖更新。

若仅本地试编译，可用 JDK keytool 在自建 keystore 目录生成测试密钥，别将测试密钥用于正式分发。例如：

keytool -genkeypair -keystore development.jks -alias codexpocket -keyalg RSA -keysize 2048 -validity 3650

命令会交互询问密码/证书资料。把生成文件放到你的项目 android/keystore，再在本地 Gradle 中匹配密码与路径；不要上传密钥或明文凭据。

使用 Gradle 8.13 在 android 目录构建：

gradle --no-daemon :app:assembleRelease :app:testDebugUnitTest
gradle --no-daemon :app:assembleDebug :app:assembleDebugAndroidTest

构建界面测试 APK 不等于执行界面测试。需要安卓真机/可用模拟器及 ADB 授权后执行 :app:connectedDebugAndroidTest。

原签名发布 APK 可供新用户直接安装；将来覆盖升级须同 applicationId、同签名并增加 versionCode。自行重签名不能覆盖现有安装。

架构与协议

安卓通过受限 HTTPS/WebSocket 接口连接自己的电脑 Tailscale 地址；配套程序用只监听本机的 Chromium 调试接口操作桌面真实控件。

手机不提交任意脚本/选择器/CDP 指令。操作绑定聊天/控件与版本，用 UUID 回执防重复；断线不自动重放。

API 和事件细节以 companion/src/types.ts、server.ts、desktop.ts 及测试为准。版本 3 保留基础操作，并增加菜单/问题/上下文/文件/图片操作。
